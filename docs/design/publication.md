# 개인 사이트 발행

## 계약

위키와 블로그는 고정 ID와 단일 본문을 공유한다. 유형은 wiki 또는 blog이며 위키 탐색에서 블로그를 참조해도 유형과 댓글 ID는 바뀌지 않는다. 공개 입력과 원문 출처의 SHA-256을 발행 목록에 기록한다. 개인 정본에 직접 쓰지 않는다.

블로그의 최초 발행일은 수정일과 구분한다. 초안과 미래 발행 글은 HTML, 검색 색인, RSS, 사이트맵에서 제외한다. 블로그 댓글 비활성화, 중복 ID, 중복 slug, 존재하지 않는 태그와 잘못된 날짜는 빌드 오류다.

## 화면

메인의 최신 글은 최대 세 편이며 네 편 이상이면 전체 보기를 제공한다. 전체 목록은 열두 편, 본문 연속 읽기는 네 편씩 정적 페이지로 나눈다. 본문은 공통 렌더러를 사용하며 각 글의 앵커와 각주를 분리한다.

검색은 한글 조합 완료 후 실행한다. 검색어의 각 낱말과 선택 태그는 AND로 결합한다. 유형별 개수는 검색어와 태그를 적용한 결과에서 계산한다. 유형을 바꾸면 첫 페이지로 이동한다. 검색 URL은 검색어, 유형, 태그, 페이지를 복원한다.

## 입력

`publication/`은 공개 문서 입력이며 `publication-manifest.json`이 출처와 해시를 기록한다. 공개 투영을 가져올 때 원래 사이트의 공개 입력 검사를 먼저 실행하고 `node product/import-publication.mjs <공개 사이트 루트>`를 사용한다. 이미 발행한 본문을 임의로 블로그로 재분류하거나 발행일을 만들어 넣지 않는다.

`publication.config.json`은 개인 소개, 포트폴리오, 프로젝트와 댓글 설정을 관리한다. 없는 개인 영상과 추천은 표시하지 않는다. `topics.json`은 네 분야의 주제와 태그 별칭을 정의한다.

## 검증

- 발행: 초안·미래 글 제외, 잘못된 날짜·태그·댓글 설정 거부
- 목록: 0·1·3·4·5·8·9·12·13편 경계에서 누락·중복 없음
- 순서: 수정일 대신 최초 발행일, 같은 날짜는 고정 ID
- 검색: 한 유형·혼합·0건, 별칭, 복수 태그, 조합 입력, URL 복원
- 화면: 1440·1024·768·390·320px와 키보드·움직임 감소
