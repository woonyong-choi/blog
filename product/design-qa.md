# 화면 검증

## 비교 대상

- 원본: https://culturedcode.com/things/ 및 support, features, blog
- 구현: 로컬 정적 서버의 /things/ 이하
- 지원 첫 화면: 두 탭 모두 CSS 1440×1000, devicePixelRatio 1로 맞추고 한 번의 비교 입력에서 두 캡처를 함께 확인했다.
- 모바일: CSS 390×844에서 문법 문서·지원 목록·슬라이드를 확인했다.

## 수정한 차이

| 차이 | 수정 | 재확인 |
|---|---|---|
| 홈 아이콘과 이름이 원본보다 큼 | 이미지 표시 폭을 300에서 실측 250px로 변경 | 홈 화면 |
| 홈 소개의 폭과 줄 높이 차이 | 440px, 1.25 비율로 변경 | 홈 화면 |
| 지원 카드 아이콘이 작음 | 카드 안 스프라이트를 실측 48px로 변경 | 수정 후 지원 첫 화면 비교 |
| 첫 카테고리와 카드 간격 차이 | 검색 아래 공간, 제목 아래 간격, 첫 카드 최소 높이 조정 | 수정 후 지원 첫 화면 비교 |
| Cloud 대표 카드와 짧은 링크의 배치 차이 | 대표 카드 옆에 링크 네 개를 묶음 | 생성 HTML과 지원 목록 |
| 기본 사이트 토큰 감사가 참고 자산을 수정 대상으로 판정 | 참고 자산을 해시로 보존 검증, dist는 생성물 검사로 분리 | 기존 사이트 빌드 통과 |

| 휴대폰 이미지가 본문 전체 폭으로 확대됨 | 실제 프레임·설명과 미디어의 2열 배치 적용 | 외부 페이지에서 프레임 371px, 화면 281.0625px, 넘침 없음 확인 |

## 필수 시각 항목

- 글꼴: simple에서 첨부와 원본 기준 시스템 글꼴로 재정의했다. 베이스 글꼴은 변경하지 않았다.
- 배치: 지원 본문 680px, 확장 미디어 900px, 두 칸·세 칸 카드, 긴 글 피드 구조를 적용했다.
- 색과 토큰: simple 테마의 역할 변수로 사용한다. 첨부 참고값과 원본 실측값을 테마에 정의했다.
- 이미지: 로컬 원본 자산과 아이콘 스프라이트를 사용했다. 임의 그림으로 대체하지 않았다.
- 콘텐츠: 한국어 더미 내용으로 원문과 문단 길이가 다르다. 전체 문법 페이지는 의도적으로 예시가 많아 원본보다 길다.

## 동작 확인

검색에서 Markdown 문서로 이동, 기기 탭 전환, 독립 슬라이드 전환과 방향키, 홈 영상 재생, 모바일 가로 넘침 없음, 외부 미리보기의 코드 복사와 데모 폼 검증, 화면의 콘솔 오류 없음까지 확인했다. 자동 검사는 URL 안전성, 중첩 구성 요소 ID·각주, 잘못된 문법 실패, 전체 문법 렌더링을 검사한다.

## 판정

지원 문서와 문법을 검토할 수 있는 구현이다. 지원 화면의 큰 배치·아이콘·여백 차이는 수정 후 재비교했다. 모든 원본 페이지와의 픽셀 단위 일치 판정은 하지 않았다. 플랫폼·회사·소셜 페이지는 공통 문서 레이아웃의 더미이며, 외부 서버 기능은 데모 입력으로 제한된다. 개인 사이트 정보 설계는 다음 작업이다.

## 동작·반응형 재검토

원본의 shared.min.js, shared.css, things.css, support.min.js, support.css와 브라우저의 실제 상태를 대조했다.

- 소개 영상: 재생 전 숨김, 재생 후 표시, Play/Pause/Replay 아이콘, 거리 비례 스크롤(1600px/s, 최대 1000ms, swing 곡선, 50px 여유)을 연결했다. 브라우저에서 재생 및 일시정지 상태를 확인했다.
- 기능 영상: 무음 인라인 재생과 별도 Play 버튼을 연결했다. Magic Plus는 세 개의 탭 대신 하나의 기기 플레이어와 세 재생 버튼으로 변경했다. 두 번째 버튼 클릭 후 실제 src가 6-magicplus-2.mp4로 바뀌고 해당 버튼만 Pause 상태인 것을 확인했다.
- 갤러리: 겹친 패널의 visibility를 전환해 모든 패널이 높이 계산에 참여한다. 블로그 첫 갤러리는 1→2 전환 전후 높이 558px을 유지하고 선택된 패널은 한 개였다. 원본처럼 별도 페이드 전환은 없다.
- 지원 카드: hover의 120ms 이동·그림자, active 배경을 반영했다. 390px 화면에서 폭 345px의 한 열 목록과 왼쪽 아이콘을 확인했다. 더미 본문의 줄바꿈 때문에 카드 높이는 원문과 다르다.
- 후기: 740px 미만에서는 Show More Posts로 목록을 누적한다. 모바일에서 두 묶음이 함께 표시되는 것을 확인했다. 큰 화면에서는 이전/다음으로 교체하며 끝에서 순환하지 않는다.
- 검색: 250ms 입력 대기, 한 글자 안내, 아이콘·제목·설명, hover/active 상태를 추가했다. Markdown 검색으로 해당 내부 문서가 표시되는 것을 확인했다. 검색 대상은 로컬 더미 문서이며 원본 서버의 검색 순위와 같다는 의미는 아니다.
- 지원 문서의 platform 문법을 별도로 추가했다. ?platform=iphone으로 iPhone & iPad가 선택되는 것을 확인했다. 이후 플랫폼 블록에도 선택을 전달한다.
- 제품·지원 목록·기능 설명·푸터에 각각의 반응형 분기점을 적용했다. 390px 홈에서 모든 자원 로드 후 가로 넘침이 없음을 확인했다.
- 스타일과 동작 값의 정본은 design-tokens/themes/base/simple이며 블로그에는 검증된 내보내기만 반영했다.

### 남은 일치 범위

100% 일치로 판정하지 않는다. 더미 본문의 줄바꿈, 모든 내부 페이지의 고유 배치, 후기 카드 높이와 전체 페이지의 픽셀 비교는 아직 완전 일치가 검증되지 않았다. 빌드 성공과 동작 검증은 전체 사이트의 시각적 동일성을 증명하지 않는다.

- simple의 글꼴은 이번 첨부 파일과 원본의 시스템 글꼴 계열로 재정의했다. 베이스의 font.sans 값은 변경하지 않았다. 첫 기능 영상은 브라우저에서 원본과 같은 640px 폭으로 확인했다.


## 홈·기능·블로그 실측 재검토

1440×1000과 390×844의 같은 브라우저 viewport에서 원본과 외부 미리보기를 대조했다. 이전 CSS가 캐시에 남아 새 HTML에 오래된 배치가 적용되는 문제를 발견하여 테마·스크립트 해시를 자산 URL에 반영했다.

- 홈: 1440px에서 큰 이미지 시작점은 원본 716.41px, 구현 716.50px이었다. 기능 소개 섹션 높이는 모두 1386.78px이었다. 후기의 데스크톱 4×2 배치, 모바일 2열 누적 표시, 제품 배경 이미지, 인용문 말풍선, 소셜 SVG와 뉴스레터를 다시 구성했다.
- 모바일 홈: 390px에서 로고 폭 232.875px과 높이 279.906px을 원본과 동일하게 확인했다. 더 보기 클릭 후 두 후기 묶음이 동시에 표시되며 가로 넘침이 없었다.
- 기능: 14개 소개 섹션과 마지막 블로그 연결, 8개 세부 기능 목록을 렌더링한다. 제품·후기는 홈 데이터에서 재사용한다. iOS 탭 선택과 실제 영상 재생 15.55초 진행, 일시정지를 브라우저에서 확인했다.
- 지원: 검색 아이콘을 원본의 32px 표시 폭으로 수정했다. 모바일 추천 검색어는 80% 폭에서 줄바꿈한다. 카드 제목과 본문 사이 간격, 글자색을 실측값으로 변경했다.
- 블로그: 본문 680px와 확장 이미지 900px을 유지하며 긴 글 구조를 구성했다. 대화 슬라이드는 클릭 1→3, 방향키 3→4 전환과 선택 상태를 확인했다. 본문 이미지는 깨진 항목이 없었다.

위 기록은 해당 화면과 동작의 확인 결과다. 모든 내부 페이지의 고유 레이아웃과 모든 viewport를 확인했다는 뜻은 아니다. 더미 문단의 언어·줄바꿈은 원문과 다르며 목표 작업은 계속 진행 중이다.

## 내부 페이지와 모바일 보완

- 지원 상세 검색창의 상단 여백·높이·모서리와 제목을 실측했다. 1440px에서 제목 시작점 223.81px, 높이 59.58px를 확인했다. 원본에 없는 자동 목차를 제거하고 전체 문법 예시는 별도 경로로 옮겼다.
- 블로그 확장 이미지의 가로 넘침을 수정했다. 검사는 `innerWidth` 대신 `documentElement.clientWidth`와 `scrollWidth`를 비교한다. 390px viewport에서 둘 다 375px인 것을 확인했다.
- 문의 양식의 라디오·체크박스는 실제 SVG 자산을 사용한다. 로컬 검증 확인 후 전송 버튼이 활성화되고, 제출 시 외부 전송 없이 결과를 표시하는 것을 브라우저에서 확인했다.
- 뉴스레터 입력 검증과 결과 표시를 확인했다. 소개·채용은 일러스트와 반투명 패널로 구분하고, 법적 문서는 더미 본문과 제목 계층을 사용한다.
- 기능 페이지의 세 가지 알림 설명과 보충 문단, 네 가지 목록 편집 설명, 재생 버튼 위치, 두 열 목록의 세로 순서를 수정했다. 390px에서 기능 14개와 가로 넘침 없음, 누락 이미지 없음을 확인했다. 공유 플레이어는 두 번째 영상을 선택하여 실제 재생 8.61초 진행과 선택 버튼만 일시정지 상태가 되는 것을 확인했다.
- 상태 화면, 보도 자료의 검토용 ZIP 다운로드, 생산성 가이드의 내부 이동을 추가했다. 이 화면들의 모든 시각 상태는 아직 대조 완료가 아니다.

미검증 상태와 전체 사이트 동일성은 위 개별 검사 결과로 대체하지 않는다. 목표는 계속 진행 중이다.

## 홈 높이와 추가 상호작용 확인

- 768px viewport: 제품 섹션 906.9375px, 후기 섹션 985.6875px로 원본과 동일하게 측정했다. 제품 배지의 고정 높이가 좁은 카드에서 비율을 깨뜨리는 문제와 소셜 SVG의 기준선 차이를 수정했다.
- 1440px viewport: 기능 섹션 1386.78125px, 제품 887.25px, 후기 985.6875px, 푸터 303.0625px로 원본과 동일했다. 도입부는 0.09375px 차이가 있으며, 더미 인용문·뉴스레터의 전체 높이는 완전 동일하지 않다.
- 상태 보드: 상단 시작점 331px, 상태 영역 높이 100px를 원본과 동일하게 확인했다. 과거 기록 버튼은 `aria-expanded`와 문구가 함께 바뀌며 패널을 펼친다.
- 전체 문법 페이지: 29개 복사 버튼, 2개 갤러리, 2개 입력 양식, 표·탭을 확인했다. 첫 JavaScript 코드의 실제 클립보드 내용과 `Copied` 표시를 확인했다. 390px viewport에서 clientWidth/scrollWidth가 모두 375px였다.
- 단축키 문서: 13개 그룹의 표와 27개 언어 선택 옵션을 Markdown으로 제공한다. Korean 선택 시 설정된 예시 키가 바뀌고, 도움말 팝오버가 열리고 Escape로 닫히는 것을 확인했다. 390px에서 가로 넘침이 없었다.

- 도움말은 원본처럼 클릭으로 여는 팝오버로 변경했다. 데스크톱에서 277.5px 폭, 열림 상태, Escape 닫기를 확인했다. 화면 아래에 공간이 없으면 위쪽을 선택하고 스크롤 시 닫는다.
- Markdown의 `::highlight::`와 취소 작업 `- [~]` 렌더링을 추가했다. 코드 구간·이스케이프·중첩 강조·HTML 비실행을 포함한 회귀 검사가 통과했다.

- 이미지 로드 전의 레이아웃 이동을 발견하여 SVG 121개와 새 래스터 자산 9개의 원래 크기를 추가했다. 일반 Markdown 이미지에도 크기를 반영한다. 캐시를 끈 실제 브라우저에서 제품 배지 5개가 아직 로드되지 않은 시점에도 40px 높이를 확보하고, 모바일 제품 섹션이 원본과 같은 1464px을 유지하는 것을 확인했다.
- 최종 검사: 문법 테스트 5개, 테마 테스트 25개, 테마 생성물 28개 동등성 검사, CSS 토큰 검사, 기존 문서 309개 빌드와 310개 페이지 검사가 통과했다. 제품 빌드는 73개 페이지와 244개 자산의 링크·앵커·테마 해시를 확인했다.

- 도입부의 소수점 오차도 수정했다. 원본의 23.994px 글자 크기와 이에 비례하는 아이콘·로고 간격을 반영했다. 최종 도입부 높이는 1440px에서 1134.65625px, 390px에서 808.53125px로 원본과 동일하게 확인했다. 앞선 도입부 0.09375px 차이 기록은 이 수정으로 해소됐다.

## 가격·다운로드·보도 자료·상태 보드 보완

- 가격 페이지를 일반 문서에서 전용 레이아웃으로 수정했다. 홈과 같은 제품 카드 컴포넌트를 사용한다. 1440px에서 제목 좌표와 크기, 카드 4개의 좌표와 211.5×216.484375px 크기가 원본과 같았다. 390px에서는 카드 345×116.484375px와 한 열 전환이 같고, 더미 설명의 한 줄 차이만큼 아래 위치가 달랐다.
- 원본 체험 버튼은 설명 문서가 아니라 파일 다운로드였다. 실행 파일이 없는 검토용 ZIP을 연결하고 브라우저에서 다운로드 완료와 현재 페이지 유지를 확인했다. 원본 기기별 링크는 App Store로 이동하므로 임시 내부 소개 문서를 외부 연결로 바꿨다.
- 보도 자료의 제목 줄 높이와 버튼 간 줄바꿈을 수정했다. 원본 버튼의 기본·hover·active·focus 상태를 토큰으로 반영했다.
- 상태 보드는 420px 이하에서 전체 폭, 17px 기준 글자, 두 열을 유지한다. 390px에서 보드 폭 375.34375px, 두 표시 칸의 폭 232.96875px·116.5px와 높이 38.25px를 원본과 동일하게 확인했다. 문서 가로 넘침은 없었다. 둥근 글꼴과 어두운 배경 헤더 상태, 펼칠 때 배경 이동을 추가했다.

- 같은 데스크톱 조건에서 재생 후 스크롤 568px, 영상 상단 148.40625px, 1425×801.5625px 영상 영역을 확인했다. 양쪽 영상이 실제로 진행되며 별도 재생 버튼으로 일시정지됐다.
- 390px에서 닫힌 도입부 808.53125px, 열린 도입부 1019.46875px, 영상 375×210.9375px로 같았다. 재생 버튼도 원본과 같은 x=43.8125px, y=584.96875px, 287.359375×40.5px로 맞췄다.
- 수상 표시 줄 높이, 수상 이미지의 기준선·그림자, 뉴스레터 마지막 여백을 보정했다. 앞선 인용문·뉴스레터의 2.390625px 높이 차이는 해소됐다.
- 위 수치는 해당 viewport와 상태의 구조 확인이다. 더미 문장의 글리프·모바일 줄바꿈을 원문과 동일하게 만든다는 뜻은 아니다.
